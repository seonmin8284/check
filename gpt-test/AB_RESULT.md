## 0. 2차에서 무엇이 잘못됐나

2차는 arm 당 **1회 실행**으로 A F1 0.950, B 0.877 을 보고하고 "A 채택"을
권고했다. 부트스트랩 CI `[+0.026, +0.125]` 도 붙였다. 그 CI 는 *행* 재표집
분산만 잡고 *파스* 재추출 분산은 잡지 못한다. `run_csv*.py` 에는 temperature 도
seed 도 없다 — 같은 프롬프트가 매번 다른 파스를 낸다.

arm 당 3~4회 돌려 그 분산을 실제로 쟀다.

## 2. A rep1 은 운이 좋았던 게 아니다

`A rep1 이 rep2·rep3 이상인 source: 8/8`. 독립 추출이라면 (1/3)⁸ ≈ **0.015%**.

| arm | rep1 이 최고인 source |
|---|---|
| A | **8/8** ← 그래프가 이 실행에 맞춰졌다 |
| B | 6/8 |
| C | 2/8 |

capability graph 의 EXPANSION 규칙들이 A rep1 의 파스를 보며 작성됐다. 코드에
흔적이 남아 있다 — `PRICE_GATE` 독스트링의 `invest/2 g2` 는 A rep1 의 출력이다.
C 의 rep1 편향이 2/8 인 것이 대조군 역할을 한다: `route_intent.py` 는 C 에
과적합돼 있지 않고, 그런데도 C 는 진다. **즉 C 의 열세는 측정 편향이 아니라
진짜 스키마 열세다.**

`ab_fit.py` 는 규칙 *선택*을 기계화해 이 편향을 걷으려 했지만, 규칙 *작성*의
편향은 걷지 못한다고 스스로 밝혀놨다. 그 잔여 편향의 크기가 이제 측정됐다 —
**약 +0.06 F1**.

## 4. C 는 단일로는 최악, 앙상블에서는 필수

C 의 열세는 어느 조건에서도 견딘다.

| 비교 | Δ | 부호검정 | 실행쌍 |
|---|---|---|---|
| A−C | +0.0712 | A27:C12, p=0.024 | 9/9 A 우세 |
| B−C | +0.0650 | B23:C9, p=0.020 | 9/9 B 우세 |

goal 분해(A/B)가 flat intent 분류(C)보다 **+0.07** 낫다. 스키마는 유지한다.

**그런데 C 를 버리면 안 된다.** §5 참조 — 앙상블 구성원으로서의 가치는 단일
성능과 무관하다.

## 5. 앙상블 — 같은 예산이면 반복보다 다양성

결손의 큰 몫이 "같은 arm 이 실행마다 다른 답을 낸" 행에 있다. 파스가 안정한
행은 F1 0.91~0.92, 흔들리는 행은 0.68~0.81 이다.

| arm | 파스 안정성 (신규추출 2회 동일) | 안정행 F1 | 불안정행 F1 |
|---|---|---|---|
| A | 72% | 0.921 (n=48) | 0.806 (n=19) |
| B | **84%** | 0.910 (n=56) | 0.683 (n=11) |
| C | 67% | 0.865 (n=45) | 0.705 (n=22) |

호출 예산을 고정하고 구성을 쓸었다 ([ensemble_sweep.py](ensemble_sweep.py), dev 45행,
rep1 제외):

| 예산 | 최적 구성 | F1 | P | R | 단일 대비 |
|---|---|---|---|---|---|
| 1회 | B 단일 | 0.8767 | 0.865 | 0.889 | — |
| 2회 | B×2 만장일치 | 0.8867 | 0.917 | 0.858 | +0.010 |
| **3회** | **A+B+C 다수결≥2** | **0.9101** | 0.915 | 0.906 | **+0.033** |

같은 3콜에서:

```
A+B+C 다수결≥2   0.9101   ← 서로 다른 프롬프트 한 번씩
B×3 만장일치      0.8966
B×3 다수결≥2     0.8688   ← 한 프롬프트 세 번
A×3 다수결≥2     0.8744
```

**한 프롬프트를 세 번 돌리는 것보다 다른 프롬프트를 한 번씩 돌리는 게 낫다.**
메커니즘은 오류 상관이다 — 오류 자카드가 같은 arm 0.632, 다른 arm 0.501.
같은 프롬프트는 같은 자리에서 같이 틀려 투표해도 상쇄가 안 된다.

배포: [ensemble_predict.py](ensemble_predict.py).

## 6. 프롬프트 결정성 작업 — 하지 않음

B 를 더 결정적으로 만드는 작업을 검토했고 **접었다.**

1. B 는 이미 `strict: true` json_schema 에 `domain`/`facet`/`horizon`/엔티티
   타입까지 enum 으로 묶여 있다. 스키마 제약 레버는 소진됐다.
2. B 의 dev 불안정은 **7행**이고 원인이 흩어져 있다 — goal 개수 2, domain·facet
   2, 엔티티 구성 2, 기타 1. 겨냥할 단일 레버가 없다.
3. **상한을 쟀다.** B 가 완벽히 결정적이 되어 항상 최빈 파스를 낸다면
   0.8767 → **0.8991 (+0.022)**. §5 의 앙상블이 이미 준 +0.033 보다 작고, 같은
   잡음을 원천으로 하므로 더해지지도 않는다.

## 7. 그래프 재적합 — 실행했으나 적용하지 않음

[refit_graph.py](refit_graph.py) 로 dev 45행에서만 재적합했다. 두 후보가 나왔고
**둘 다 기각했다.**

| 후보 | dev 이득 | 기각 사유 |
|---|---|---|
| `JUDGMENT_BUNDLE[('issuer','current')]` → `('get_stock_news',)` | +0.0105 | 이 자리가 걸리는 dev 행이 **1개**(invest/4) |
| 규칙 24개 → 17개 | +0.0000 | 제거된 7개 중 **5개가 dev 발화 0회** |

두 번째가 특히 중요하다. backward elimination 이 "빼도 안 나빠진다"고 판정한
규칙 중 다수는 **dev 에서 아예 발화하지 않는다.** 그건 무용하다는 증거가
아니라 증거가 없다는 뜻이고, 빼면 근거 없는 도박이다.

```
   0  non-equity index→industry channel           발화 0 — 증거 없음
   0  corporate_event on price→announcement+news  발화 0 — 증거 없음
   0  index-relative assessment→price             발화 0 — 증거 없음
   0  internal regulation→policy                  발화 0 — 증거 없음
   0  next-step→guide                             발화 0 — 증거 없음
   2  comparative assessment                      발화하나 점수 불변
   1  document→policy                             발화하나 점수 불변
```

**dev 45행으로는 24규칙 그래프를 더 맞출 수 없다.** 이게 결론이다.

## 9. 판단

> ⚠️ 판단 1·3 은 §11 에서 갱신됐다. 1 은 더 강해졌고(B 가 앞선다), 3 은
> 약해졌다(+0.0185 → +0.012).

1. **A 채택 근거 없음.** 2차의 "A 채택" 권고는 철회한다. 신규 추출에서 A−B 는
   +0.009, p=1.000 이다. 프롬프트 설계로는 두 안이 구분되지 않는다.
   → §11: 미노출 116행에서는 **B 가 +0.030 으로 앞선다.**
2. **단일 arm 을 골라야 한다면 B.** F1 이 같고 분산이 1/9, 파스 안정성이
   84% 대 72% 다. 같은 질의에 같은 함수를 부르는 쪽이 운영에 낫다.
3. **3콜을 쓸 수 있다면 A+B+C 다수결.** holdout 기준 +0.0185. C 는 단일로는
   최악이지만 오류가 덜 상관돼 있어 앙상블에서 값을 한다.
   → §11: 미노출 표본에서 **+0.012 로 축소.** 비용 대비 판단이 갈린다.
4. **그래프도 프롬프트도 지금 데이터로는 더 못 맞춘다.** 다음 개선은 규칙이나
   프롬프트가 아니라 **골든 확장**에서 나와야 한다.
   → §11: 골든이 273행이 되면서 이 조건이 해소됐다. 재적합이 가능해졌다.

## 10. 한계

- **holdout 이 진짜 처녀지가 아니다.** 동결이 3차 측정 시점에 이뤄졌고,
  그래프와 프롬프트는 그 전에 67행 전체를 보며 만들어졌다. +0.0185 는 *동결
  이후 내린 결정(앙상블)* 에 대해 유효하지만, **0.8625 를 일반화 성능으로
  읽으면 여전히 낙관적이다.**
- **holdout 은 소진됐다.** 다음 라운드는 새로 잘라야 한다.
- **22행은 작다.** holdout 의 ±1행이 F1 을 0.02 넘게 흔든다.
- **골든과 route.py 가 함께 진화했다.** 이 지표는 프롬프트가 아니라 "라우팅
  테이블이 골든에 얼마나 맞는가"를 재고 있을 수 있다.
- `ext_div`·`ext_index` 는 세 arm 모두 낮다. 프롬프트가 아니라 route.py 에
  배당·지수 밸류에이션 경로가 덜 갖춰진 쪽에 가깝다.

## 11. 4차 — 골든 273행 확장과 미노출 표본 148행

골든이 67 → 99(`ext_edge` 32행 신규) → **273행**(`work`/`invest` 각 100행
전량 라벨링)으로 늘었다. 이로써 **적합에 한 번도 쓰인 적 없는 표본 148행**이
확보됐다.

- `ext_edge` 32행 — 최소대립쌍 위주. 그래프·프롬프트 어디에도 노출된 적 없음.
- `work`/`invest` idx 13~99 중 116행 — 파스는 rep1 에 이미 있었으나 **라벨이
  없어 적합에 쓰일 수 없었다.** 추가 API 호출 0회로 측정됐다.

### 결과 — 0.88 이 아니라 0.63

| 구성 | 기존 26행 | ext_edge 32행 | **신규 116행** |
|---|---|---|---|
| A 단일 | 0.9600 | 0.6094 | **0.5887** |
| B 단일 | 0.8947 | 0.6250 | **0.6187** |
| C 단일 | 0.7973 | 0.5137 | 0.5863 |
| A+B+C 다수결 (3콜) | 0.9189 | 0.6327 | **0.6306** |

**독립적인 두 신규 표본이 같은 값을 가리킨다** — ext_edge 0.633, 신규 116행
0.631. 148행이 일관되게 0.62~0.63 이다.

### A 의 우위는 허구였다 — 순위가 뒤집힌다

```
기존  26행:  A 0.9600  >  B 0.8947    (A +0.065)
신규 116행:  A 0.5887  <  B 0.6187    (B +0.030)
```

낙폭이 **A −0.371 > B −0.276 > C −0.211** 로, §2 의 rep1 편향 진단
(A 8/8, B 6/8, C 2/8) 과 순서가 정확히 일치한다. 그래프가 각 arm 에 맞춰진
정도가 곧 낙폭이다. 3차의 "A 채택 철회"에서 한 걸음 더 나가, **B 가 앞선다.**

### 앙상블 이득은 살아남되 미미하다

B 단일 0.6187 → 3콜 앙상블 0.6306 (**+0.012**). ext_edge 에서 +0.008.
§5 의 +0.033 은 적합 데이터에서만 성립하는 값이었다. 3배 비용에 +0.01 이면
채택 여부는 비용 정책이 정할 문제지 성능이 정할 문제가 아니다.

### 실패 양상 — 과호출이 아니라 오식별

호출 **개수**는 잘 맞는다 (ext_edge 골든 평균 1.31 / 예측 1.28, 신규 116행
골든 2.33 / B 예측 2.10). 틀리는 건 **어느 함수인가**다.

```
반도체 업황 뉴스 알려줘            정답 news+sector       예측 news
2차전지 테마 오늘 얼마나 올랐어?     정답 index_price       예측 index_price+sector
코스피200 공매도 잔고              정답 index_shorting     예측 +index_price
현대차 목표주가 얼마야?            정답 eval+financial     예측 eval
```

같은 `get_sector` 가 어떤 행에서는 누락, 다른 행에서는 오호출이다.
`theme→industry channel` 의 발화 조건이 거칠다. 기존 67행에는 이런
최소대립쌍이 없어 드러나지 않았다 — 여러 함수를 다 부르면 대충 맞는
데이터로 적합했더니, 하나만 정확히 골라야 하는 데이터에서 무너졌다.

### 분할 현황

`holdout` 이라는 한 이름이 "아직 안 연 것"과 "열어버린 것"을 뭉뚱그려
